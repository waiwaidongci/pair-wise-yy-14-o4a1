# hxyfront-62013 木结构榫卯构件测绘 · 离线多队批次合并

源提示词编号：8

测绘队分头进入不同古建、断网时各记一份，回站后把**构件清单、尺寸台账、病害落点图、建筑关系**挂到同一测绘批次同步合并。

## 同步语义（已逐条落地并有 40 项无头测试覆盖）

1. **同一批次**：四类成果均携带 `batchId`，在 `src/engine/merge.ts` 的 `receiveArrival` 中按批次合并。
2. **双方都改 → 双份待确认，晚到不覆盖**：每条离线记录带离站基线版本号 `baseRev`（三方版本检测）。
   晚到一方的基线版本落后于站上、且双方内容都与基线不同时，晚到记录作为候选异本挂在 `candidates`，
   记录置为 `conflict`，任何一边都不覆盖另一边，由人工裁决（保留站上 / 采用晚到，两版都进历史）。
3. **构件更换 / 截面变更 → 级联失效重算**：引用该构件的关系边立即置 `invalid`（红虚线）等待重算；
   该构件病害的修缮结论是派生数据，立即按新件重算（如"原病害随旧件剔除"）。旧关系、旧结论全部留在 `history`，旧成果可查。
4. **保存失败 → 回滚到最后确认的构件**：以构件组为落盘事务，持久化回调抛错则整组回滚；
   断点（已确认成员游标 + 首次载荷）**按队**隔离保存，状态 `partial`，修复后由该队续传，只补齐未确认的组；
   其他队到站不受影响。
5. **重传同一批次只认第一次**：同队对同批次的完成记录再次到站返回 `duplicate`，重传载荷里夹带的不同内容
   （测试里用 `FAKE-99` 伪造构件验证）一律不落库；载荷哈希固定为第一次。续传只在该队处于 `partial` 时发生，且沿用首次载荷。
6. **无批次号老草稿按测量日期归档**：`batchId` 缺失的载荷进入 `archives`（按 `measuredAt` 日期分组），只可查、绝不并入主数据。
7. **批次整体确认**：所有冲突清零、无 partial 断点后才能 `confirmBatch` 封存。

## 目录

- `src/engine/types.ts` — 领域模型（构件/尺寸/病害/关系、批次、候选异本、历史版本、断点）
- `src/engine/merge.ts` — 纯函数合并内核（无 React 依赖，可直接在 Node 下测试）
- `src/engine/seed.ts` — 演示数据：站上基线 + 甲队（先到、含换件）+ 乙队（晚到、双方改动）+ 老草稿
- `src/engine/store.ts` — React Hook + localStorage 持久化 + 一次性掉电故障注入
- `src/components/` — 批次面板、冲突裁决卡、构件/尺寸/病害落点图/关系图视图
- `test/engine.test.ts` — 40 项语义断言

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62013
npm test           # 合并内核语义测试
npm run typecheck
npm run build
```

## 页面演示路径

按"到站操作"区按钮顺序：① 甲队先到（L02/L03 更换 → 关系边失效、F-05 结论重算）→ ② 乙队晚到
（L02/F-01/R-01 三处双方改动双留）→ ③ 甲队重传（含伪造构件，被幂等忽略）→ 逐张裁决冲突 →
在"建筑关系"页对失效边按新件重接/复核维持/判废 → 整体确认批次。可先点"预置 L03 组落盘掉电"体验
保存失败、乙队照常用站、修复后续传的完整断点恢复链路。
